See where your Dynatrace subscription goes, in about 10 minutes.

A custom Dynatrace app that shows which hosts, Kubernetes namespaces, applications, monitors and buckets use your Dynatrace Platform Subscription, how much of it can be charged back to teams, and what is worth reviewing to spend less.

Version 0.12.50 Built by Mohd Daniel Hazim Amran Not an official Dynatrace product

Read-only

It reads your environment's own billing records and changes nothing in Dynatrace.

Stays in your environment

No data leaves Dynatrace. No tracking, no outside services.

Your credentials only

You install it with your own OAuth client. Nobody else needs it.

Paste it once and every command on this page fills it in for you. It is the address in your browser when you use Dynatrace, up to .com, and ends in .apps.dynatrace.com (not a company address such as dynatrace.yourcompany.com). Nothing is saved.

Install

Five steps, nothing to install on your computer. You only do steps 1 to 3 once. Already installed? Update to a newer version in about three minutes.

Showing the steps for MacWindows. Installing from Windowsa Mac?

  1. Check you have what you need 2 min

    • A Dynatrace Platform Subscription (DPS) environment. Older licence models do not write billing records, so the app would be empty.
    • Your user has the AppEngine developer and AppEngine user policies. Admins usually do.
    • Custom apps are allowed in the environment (they are by default).

    Tip: try it in a non-production environment first if you have one.

  2. Create an OAuth client for installing apps 3 min

    In Dynatrace, go to

    Account Management›Identity & access management›OAuth clients›Create client

    Give it a name such as License Consumption Explorer install, tick these three scopes, and create it:

    app-engine:apps:install
app-engine:apps:run
app-engine:apps:delete
    Copy the client ID and the client secret now. Dynatrace shows the secret only once. Keep both somewhere safe; the installer asks for them in step 4.

  3. Open a terminal in this folder 1 min

    Open Terminal (press Cmd Space, type Terminal, press Return). Type cd and a space, drag this folder from Finder into the Terminal window, and press Return. It looks like this:

    cd ~/Downloads/license-consumption-explorer

    The path may differ if you unzipped it somewhere else; dragging the folder in gets it right.

    In File Explorer, open this folder, right-click an empty space and choose Open in Terminal. On older Windows, click the address bar, type powershell and press Enter.

    You should see a prompt ending in license-consumption-explorer>.

  4. Run the installer 1 min

    Paste this and press ReturnEnter:

    bash install.sh
    powershell -ExecutionPolicy Bypass -File .\install.ps1

    It asks three questions:

    • Environment address: https://abc12345.apps.dynatrace.com
    • OAuth client ID: from step 2, starts with dt0s02.
    • OAuth client secret: from step 2. Nothing appears as you type or paste it; that is normal. Press ReturnEnter.

    It signs in with the OAuth client and uploads the app, which takes under a minute. It ends with Done and the app's address. Nothing needs installing on your computer, and the secret is not saved anywhere.

  5. Open the app and run the first-run check 5 min

    Open the app from the Dynatrace app launcher, or go straight to:

    {ENV}/ui/apps/my.license.consumption.explorer

    The first time, Dynatrace asks you to approve the app's permissions. All of them are read-only, except saving each person's own settings. The Overview should then say how many capabilities have billing records in the last 30 days.

    Finally, go through FIRST-RUN-CHECK.md in this folder. It is short, and compares the app with numbers you already trust, so you know you can rely on it.

Update to a newer version

For anyone who already installed the app. About three minutes. Everyone keeps their saved settings: ownership rules, budgets, edited rates, the Account Management connection and dismissed tips.

  1. Unzip the new version 1 min

    Unzip the new file anywhere, for example your Downloads folder. You can delete the old folder; nothing in it is needed.

  2. Open a terminal in the new folder 1 min

    Exactly as in step 3, but in the folder you just unzipped.

  3. Run the installer with the same details 1 min

    Run the installer as in step 4. Give it the same environment address and the same OAuth client as the first time: there is no need to create a new one. If you no longer have its secret, create a new client as in step 2.

    It replaces the installed version and ends with Done.

  4. Check it updated 30 s

    Open the app and reload the page. Open Help (top right): the last line shows the version, for example Version 0.12.50. If Dynatrace asks you to approve permissions again, the new version uses one more read-only permission; approving it is safe.

A tour of the app

The app opens on Home: four answers on one screen. The top row switches between three places, Home, Consumption and Cost, with Help on the right. The row under it lists that section's screens as tabs, with the timeframe and Refresh on the right. Each screen opens with one sentence that answers its question; everything below it is the detail. The (i) after the tabs says what the screen is for.

Home start here

Home
What this timeframe costs, what changed since the one before, how much can be charged to teams, and how many checks found something (Findings). Each card opens the screen with the detail.

Consumption in units: hours, GiB, sessions

Overview
How much of your usage can be charged to a team? Four checks, from used to charged to a team. Click a check to see what is in it, what stopped there and what would move it on.
Usage
What was billed, capability by capability, each in its own unit, with a daily chart. Open one to see what drives it.
Entities
Which things use the most. Five tabs: Hosts, Kubernetes (by cluster, then namespace), Applications, Synthetic monitors and Buckets (where logs, events, traces and metrics are billed). Open a host for its usage by day.
Ownership
Which hosts and namespaces have an owner, and which don't. Owners come from Dynatrace cost centres, or from simple rules you add here, such as "the team tag is the owner".
Queries
Who and what runs the queries you pay for. By source pools them by app, dashboard and service account; By person lists individual users, with names hidden until you click Show names (the choice isn't saved). Then the dashboards, notebooks and workflows that scan the most, each with an Open button.

Cost in money

Spend
With Account Management connected, finished days show what Account Management billed, and only the most recent days are estimated; a section underneath shows your budget, Dynatrace's forecast, cost in your other environments and Dynatrace's cost alerts. Otherwise: what this timeframe would cost, and how that compares with the one before, of the same length. Tabs: Cost (daily chart: click any day to see what drove it against a typical day; per capability; CSV export for finance), Why it moved (what changed, with the five hosts, apps or buckets that rose and fell the most) and What if. Commitment burn and Usage against plan appear once you enter a commitment or allowances on the Rate card.
Cost per host
Which hosts cost the most, with every capability billed on each one added up. Group by host group or monitoring mode to see the cost per group.
Findings
Usage that may be worth reviewing, such as Full-Stack hosts with no detected service, or workflows billed with no runs. Each check says what it found and, where it can be priced, an estimated range with its basis.
Team budgets
Cost per owner, against a budget you set. With Account Management connected, Dynatrace's own split by cost centre sits underneath, to check against.
Rate card
Which prices the app uses, with their real digits. Public list prices by default; connect Account Management for your contract rates, or override a rate for yourself. Clicking the List price, not your contract tag on any screen explains it and links here. From here, Compare with Account Management Preview checks whether the app's count matches Account Management's (needs the connection).

Help top right

Glossary
What the words on the screens mean, and the keyboard shortcuts.
Show tips again
Brings back the one tip shown on a first visit.
Diagnostics
The raw billing records behind every screen, with the query for each, for anyone who wants to check a number.

Column headersLists open ranked, highest first. Click a header to sort by it, for example host name A to Z or the lowest usage first; click again to reverse. Grouping, filters and sort stay in the address, so Back undoes each change and a copied link opens the same view.

Install a newer version

See Update to a newer version above: unzip, open a terminal in the new folder, run the installer with the same OAuth client, then check the version under Help.

Remove the app

In a terminal in this folder, with the same OAuth client:

export DT_APP_OAUTH_CLIENT_ID="dt0s02.YOUR-CLIENT-ID"
export DT_APP_OAUTH_CLIENT_SECRET="YOUR-CLIENT-SECRET"
npx dt-app uninstall --environment-url {ENV}
$env:DT_APP_OAUTH_CLIENT_ID="dt0s02.YOUR-CLIENT-ID"
$env:DT_APP_OAUTH_CLIENT_SECRET="YOUR-CLIENT-SECRET"
npx dt-app uninstall --environment-url {ENV}

Replace the two placeholders with your client ID and secret. Each person's saved settings are removed with the app.

Install by hand, without the installer

The same as what the installer does. In a terminal in this folder:

npm ci
export DT_APP_OAUTH_CLIENT_ID="dt0s02.YOUR-CLIENT-ID"
export DT_APP_OAUTH_CLIENT_SECRET="YOUR-CLIENT-SECRET"
npx dt-app deploy --environment-url {ENV}
npm ci
$env:DT_APP_OAUTH_CLIENT_ID="dt0s02.YOUR-CLIENT-ID"
$env:DT_APP_OAUTH_CLIENT_SECRET="YOUR-CLIENT-SECRET"
npx dt-app deploy --environment-url {ENV}
Hand a package file to a change process

The package folder holds a ready-built install package of this same version, for teams that review a file before installing. To build one yourself:

npm run package

The package appears in the out folder.

Permissions, data and security

The app asks for read access to system events, buckets and entities, plus read and write access to each user's own saved settings. It cannot change environment configuration, settings, entities, data, or other users' settings.

User email addresses are never stored or logged, and appear on screen only when someone clicks Show names on the Queries screen, for that visit only. The only optional outside connection is to Dynatrace's own Account Management, and only if a user chooses to connect it.

SECURITY-SUMMARY.md in this folder is a one-page version for a security or change review.
